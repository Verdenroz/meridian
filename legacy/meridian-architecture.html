MERIDIAN.

A regime-adaptive portfolio model: it ingests every finance-query data stream, detects the prevailing market regime, and emits per-minute allocation weights for up to 100 US-listed assets. Trained on GPUs; served in full FP32 on a small x86-64 host.

01 System — end to end

Two lanes: train offline, allocate online

Everything upstream of the checkpoints runs offline on GPU hardware. The inference host runs only the trained model — plus the same Rust DataBus that built the training data, so live features and training features come from one assembler and can never drift apart.

03 Model core — regime-conditioned throughout

A hybrid RA-GDN backbone with routed experts

The regime detector runs first; its 4-class posterior biases (α) and scales (β) every backbone block and routes the mixture-of-experts. Sliding-window attention is interleaved for local precision; the temporal cascade injects slower context only when the market is surprising.

Regime detector163-dim in → 4-class posterior

Market block + portfolio summary + rolling regime EMA. Output conditions every RA-GDN block (α/β) and routes FMoE experts.

Temporal cascade3 levels · strides 60 / 390 / 1950 min

Hourly, daily, and weekly GDN stacks. Their context is injected into the fast path only when gated by surprise.

Event encoder18 event types → 64-dim tokens

Discrete happenings become attended tokens whose influence decays exponentially with age.

Episodic memoryexact k-NN · 50k states · 8 retrievals

FAISS buffer of surprising past market states (>2σ). Retrieved neighbors join fusion as extra tokens — "when did the market last look like this?"

Auxiliary prediction headnext-step return + volatility

Not traded on directly — its error is the surprise signal that gates the cascade and admits states to memory.

04 Outputs — what comes back

Two heads, one shared backbone

Both heads emit a full allocation vector every minute: temperature-scaled softmax over the active universe, so weights are non-negative and sum to exactly 1. Inactive slots are masked to −∞ and receive precisely zero.

Meridian-R

objective: differential Sharpe ratio (return-seeking) + turnover penalty

The growth head. Trained to maximize risk-adjusted return with a bias toward capturing upside. Checkpoints selected on validation DSR.

Meridian-S

objective: rolling-Sharpe loss + volatility auxiliary

The stability head. Trained to maximize the Sharpe ratio of the realized path — smoother equity curves, tighter drawdowns. Checkpoints selected on rolling-Sharpe loss.

06 How you drive it

An operator's session, start to finish

Meridian is driven from the Makefile — there is no app layer. The operator defines the universe, runs the pipeline in order, and consumes weights and reports. Training stages run in tmux and auto-resume from stage-best checkpoints.

  1. configureDefine the universe & credentials

    Pick up to 100 symbols (grouped by GICS sector) and set feed credentials — FRED, HF token, and a real SEC user-agent so EDGAR text features don't collapse to zeros.

    portfolio_symbols.txt.env
  2. collectBuild the dataset

    The Rust DataBus ingests every stream, the FinBERT sidecar scores text, and the pipeline lands mmap shards plus FDA synthetic windows.

    make sidecarmake collect FDA_DEVICE=cudamake stats
  3. trainPretrain, then attach the heads

    Phase 1 learns market structure self-supervised (TCP); Phase 2 warms up cross-asset fusion, then trains the return head and the Sharpe head against portfolio objectives.

    make pretrainmake portfolio-returnmake portfolio-sharpetmux attach -t portfolio
  4. validateBacktest before trusting

    Evaluate the final checkpoints on the held-out test region; review DSR, Sharpe, turnover, and drawdown in the generated reports.

    make backtestreports/
  5. serveRun live on the inference host

    The Framework Desktop runs the DataBus and the FP32 model in-process — full text teachers, exact-k-NN memory — and emits a fresh allocation vector every minute for the execution layer to act on.

    meridian-buscheckpoints/*.pt
